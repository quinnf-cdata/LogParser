CData Log Analyzer

Overview

This application is designed to view, filter, sort, and split log files generated by CData drivers.

Key Features

  • Decode hexadecimal content to readable text.
  • Split files into individual files by type or connection.
  • Sort types or connections into chronological order.
  • Combine multiple files into one file.
  • Jump to specific areas of a log with the index.

Getting Started

First Look

This application has four sets of buttons and actions that are grouped into their own categories.

  1. File Controls
  2. View Options
  3. Data Actions
  4. Filters

1. File Controls

The File Controls are similar to most other file applications.

The Choose button to open the explorer and select the files that the application should load.
Once the files are selected, the text field next to the button will populate with the files selected.
Note: The file path can be added via the text box as well.

The Load File button begins reading the selected files.

The Save As button will save the log file in view to a new file with all the applied filters and decoding.

The Reset button will reset the application to its initial state. Clearing all the loaded files and views.

2. View Options

The View Options control how the application displays the loaded log data.

Wrap Text will wrap the text within the log view and prevent vertical scrolling.

Decode Hex will convert all hexadecimal characters into readable text.

ASCII Only is disable unless the Decode Hex option is checked. This option removes non-ASCII characters from the decoded hexadecimal values.

The Refresh button will refresh all the views, filters, and indexes.

3. Data Actions

The Data Actions are used to split and sort log files by a specific type. A dialog box will appear to select which loaded files should be processed.

The Split by: button is used to split files by type into individual files.

The Sort by: button is used to sort files by type into one file.
Note: this will combine the selected files into one file.

The dropdown in this group is used to select the type. The type is an auto generated value based on specific keywords found in the log data.
If there are no types and a file is loaded, please click the Refresh button and try again.

Note: any files created while splitting or sorting will be stored in the directory of the first file selected.

4. Filters

Filters are generated based on keywords found in the loaded files. If filters are not generated after a file is loaded, please click the Refresh button.

The filters can be adjusted in %APPDATA%\CData Internal\Log Analyzer\custom_filters.json

When adding a filter, the displayname will be the name that is displayed in the application and the pattern is the keyword the application will search for in the log content.

Filter example: {"filters": [{"displayname": "HTTP","pattern": "HTTP|Res"}]}

Note: the patterns for filters read as plain text and not regular expression.

Log View

When a file is loaded, it will be display in the log view. The log view holds a tab for each loaded file and a set of navigation options for the tab currently in view.
The navigation options are:

  • Back - Goes back one page.
  • Next - Goes forward one page.
  • Go - When used with the text box, goes to a specific page.

Other options are Search and Reload Index.

The Search button, when used the the text box to its left, will search the loaded data for a specific keyword

The Reload Index button is used to regenerate the current index for the file in view.
This option should be used when there is an issue with the file's index.

Index View

The Index View is an auto generated tree of connections and notable data found in the file content.

Most of the items within the tree are double-clickable. When an item is double-clicked, the application will jump to the line that contains the item.
Some items are not double-clickable as they are generated by the application and do not have an actual line, e.g. Version Date.
